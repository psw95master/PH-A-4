### 2-3. 쿠팡 API 는 두 종류다

## 3. 확정 사항

### 3-1. 소싱 채널 = 알리익스프레스

`ko.aliexpress.com/w/wholesale-{키워드}.html` 의 HTML 에 상품 데이터가 JSON 으로 박혀 있다 (`itemList.content`). **크롬 없이 서버에서 60개/페이지**를 뽑는다.

뽑히는 값: `상품ID · 상품명 · 정가 · 판매가 · 할인율 · 별점 · 판매량`

**크롬이 필요 없어진 것이 이 세션의 핵심 변화다.** 예약 실행이 로컬 크롬을 붙잡을 수 있는지가 `260828` 미확정 항목이었는데, 문제 자체가 사라졌다.

### 3-2. 연령 표기 규칙 폐기 → 키워드로 대체

**알리 상세 페이지가 서버로 안 읽힌다.** `200` 으로 열리지만 75KB 껍데기라 `适用年龄` 이 없다. 상세 정보를 JS 로 나중에 불러오는 구조다.

그래서 연령 표기 확인 규칙을 뺀다. 대신 **A2·A3 키워드를 성인 등급으로 못 박아** 어린이제품이 검색 결과에 들어오지 않게 한다.

- `A2 프라모델` → `MG 건담`
- `A3 인형` → `디자이너 아트토이 인형`

⚠️ **체크를 빼도 법적 책임은 남는다.** 어린이제품안전특별법의 판단 기준은 표기가 아니라 제품의 실질이다. 키워드 고정은 리스크를 줄이는 장치지 없애는 장치가 아니다.

`260831 확정`

### 3-3. 하루 14개 + 후보 부족 표시

항목당 1개씩 14개. **통과 후보가 2개 이하인 항목에는 `물량 얕음` 표시**를 붙인다. 규칙을 흔들지 않으면서 "이 항목은 애초에 물건이 없다"는 정보를 10일 컷 판단에 넘긴다.

버린 안 — 통과율 좋은 항목에 몰아서 10개. 항목별 표본 수가 달라져 컷 판단이 흐려진다.

### 3-4. 슬랙 일일 보고

- 채널 `C0BLP69RPTJ` (`perrys-world-hq`)
- **매일 오전 9시** (주말 포함)
- 기존 봇 토큰(`~/.secrets/agents-in-slack.env`)으로 직접 게시. 봇을 깨우지 않는다
- 보고 형식 — 항목 제목 아래 불릿 4줄
  ```
  A1. 피규어  ·  후보 5개

  •  {상품명}
  •  알리 ₩71,078 ＋ 배송 ₩4,425 = 원가 ₩75,503
  •  최소 판매가 ₩104,000 · 마진 ₩21,399 (20%)
  •  ★4.8 · 1,000+ 판매 · 상품 보기 →
  ```
- 불릿은 `•`. 슬랙에서 `*` 는 굵게 표시로 먹혀 글자가 깨진다
- 「페리가 판단하실 것」·「가정」 블록은 **매일 붙이지 않는다.** 전제값을 바꾼 날에만 한 줄

### 3-5. 마진율은 국내 시세 없이도 나온다

시트 수식상 마진율은 `(결제가 − 해외구매가 − 국내출고 − 수수료) ÷ 결제가` 다. 국내 시세는 「국내가 대비」열에만 들어간다. 그래서 **커트라인 20% 를 넘기는 최소 판매가를 역산**해 보고한다.

```
최소 결제가 = (해외구매가 + 국내출고) ÷ (1 − 수수료율 − 커트라인)
            = (원가 + 3,000) ÷ 0.7337
```

페리는 그 가격에 국내에서 팔릴지만 눈으로 판단하면 된다.

### 3-6. 중복 방지 — 영구, 단 마스터시트 때

같은 상품이 다시 올라오지 않게 한다. **기억 기간은 영구.**

다만 알리 상품 ID 를 파일에 쌓는 임시 방식은 **쓰지 않는다.** CURV 전용 ID 체계를 만들어 시트에서 관리하고, 그 작업은 마스터시트를 만들 때 함께 한다. **현재 스크립트에는 중복 방지가 없다.**

## 6. 함정 — 이번에 밟은 것

### 6-1. 알리 IP 차단

**1.5초 간격으로 14회 연속 요청했더니 10번째쯤부터 차단 페이지(`_____tmd_____/punish`)가 왔다.** 몇 시간 동안 이 맥에서 알리 접속이 아예 안 됐다 — **크롬까지 같이 막힌다. IP 단위다.**

- 요청 간격을 **120초**로 벌렸다. 14개 × 120초 = 약 28분
- 28분이 걸려도 토큰은 안 든다. AI 가 아니라 스크립트라서
- 차단 페이지를 "후보 없음"과 구분해 `수집 실패` 로 잡도록 고쳤다. **처음엔 차단당한 4개 항목이 "후보 없음"으로 보고돼 거짓말이 나갔다**

### 6-2. 목록 가격은 쿠폰가다

```
목록  ₩71,078  (54% 할인, builderType: skuCoupon)
상세  ₩77,400  (49% 할인)
```

검색 목록에 뜨는 값은 **쿠폰이 미리 적용된 가격**이다. 실제 결제 때 그 쿠폰을 못 받으면 더 비싸진다. **원가는 상세 가격(비싼 쪽)으로 잡아야 안전하다.** 현재 스크립트는 목록 가격을 쓰고 있어 원가가 과소 추정된다.

### 6-3. 배송비를 모른다

알리 검색 결과에 **배송비가 안 나온다.** 시트의 타오바오 기준값 `¥21.5`(₩4,425)를 대신 넣었다. 그런데 확인해보니 그 상품은 **무료 배송**이었다. 원가가 과대 추정된다.

**6-2 와 6-3 이 반대 방향으로 작용한다.** 쿠폰가는 원가를 낮추고 배송비 가정은 원가를 높인다. 우연히 상쇄될 뿐 둘 다 틀렸다.

### 6-4. 한국 배송은 된다

`260831` 실측. 상품 페이지에 `무료 배송 · 배송: 9월 05일 - 10일` 로 한국 도착 예정일이 뜬다. 로케일이 `KO/KRW` 로 잡혀 있고 배송 불가 표시는 없다. **알리 상품이 한국에 안 온다는 걱정은 근거가 없다.**

## 7. 미확정

1. **알리 실제 결제가** — 목록의 쿠폰가와 상세 가격이 다르다 (`6-2`). 상세를 읽으려면 크롬으로 상품당 1회씩 열어야 한다. 시간·차단 위험이 는다
2. **알리 배송비** — 목록에 없다 (`6-3`). 상세를 읽어야 확정된다
3. **국내 시세** — 자동 경로가 없다. 쿠팡 파트너스 API 가 유일한 우회로. 페리 가입·승인 필요
4. **파트너스 API 한도** — `시간당 10회 / 1회 10개` 는 블로그 출처. 공식 문서 미확인
5. **전제값이 두 벌** — 수수료·환율·국제배송비·커트라인이 구글 시트와 `report.py` 양쪽에 있다. 시트에서 커트라인을 바꿔도 스크립트는 모른다. **스크립트가 시트를 읽게 할지 결정 필요**
6. **항목 표도 두 벌** — 노션 `PH-B-73` 과 구글 시트 `Work Flow`. 어느 쪽이 정본인지 미정
7. **키워드 14개** — 초안 상태. `C2`(욕실장 겹침) `B1` `B2`(후보 0) 수정 필요
